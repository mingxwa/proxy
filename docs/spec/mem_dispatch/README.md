# Class template `mem_dispatch`

> Header: `proxy.h`  
> Module: `proxy`  
> Namespace: `pro::inline v4`  
> Available when: `__cpp_impl_reflection >= 202506L`

The definition of `mem_dispatch` makes use of an exposition-only type *string-literal*, which is constructible from a `char` array at compile-time and can be used as a non-type template argument.

```cpp
template <string-literal Impl, string-literal Func = Impl>
class mem_dispatch;
```

Class template `mem_dispatch` is a [dispatch](../ProDispatch.md) type for member call expressions, built on C++26 reflection. `mem_dispatch<"fun">` has the same effect as a dispatch type defined with [`PRO_DEF_MEM_DISPATCH(name, fun)`](../PRO_DEF_MEM_DISPATCH.md), and `mem_dispatch<"fun", "acc">` the same effect as one defined with `PRO_DEF_MEM_DISPATCH(name, fun, acc)`, **within the member lookup model specified below**. `Impl` names the member invoked on the implementation type; `Func` names the generated accessor.

Unlike the macro, whose generated dispatch compiles a literal `self.fun(args...)`, `mem_dispatch` reconstructs the overload set of `Impl` by enumerating members via reflection. Reflection cannot observe everything that a member call expression can use, so the supported domain is defined explicitly rather than approximated silently: a program outside this model is either *not applicable* (the convention behaves as not implemented) or, where reflection cannot even detect the deviation, has unspecified call resolution. The precise boundary follows.

## Member Lookup Model

Let `T` be `std::remove_cvref_t<decltype(self)>` for the operand `self`. Invocation of `mem_dispatch<Impl, Func>` is resolved as follows:

1. The searched classes are `T` and its transitively reachable *public* base classes, in breadth-first order with base classes in declaration order. A class that declares any public member named `Impl` — of any kind — hides its bases: they are not searched through that class, as if no `using`-declaration existed. A virtual or repeated base class is searched only once, at its first occurrence.
2. The overload set is the union of the public members named `Impl` of every searched class; sibling branches that each declare the name merge, **as if disambiguated with using-declarations**:
   - Non-template member functions form the candidate set, with cv- and ref-qualifiers, [trailing default arguments](#default-arguments), `noexcept`, explicit object parameters, and implicit conversions of arguments honored. Static member functions are callable with the object argument at any qualification. Deleted member functions participate in overload resolution and make the call not applicable when selected.
   - Member functions producing the same *effective signature* — identical object binding and parameter types, including arities enabled by default arguments — are mutually ambiguous: a call selecting that signature is not applicable and does not fall back to another overload, mirroring an ambiguous member call expression.
   - Otherwise, a data member (static or non-static) named `Impl` receives the call; its own `operator()` overloads then resolve. In particular, an accessor generated by another `mem_dispatch` is itself such a member, so accessor types compose.
3. If no searched class declares `Impl`, the dispatch is not applicable for `T`.
4. If `Impl` names both functions and data members across the searched classes, or data members in more than one class, the overload set is empty and the dispatch is not applicable for `T`.

### Default arguments

A member function with trailing default arguments is viable at every arity a member call expression could use, exactly like `self.Impl(args...)`.

## Out of Scope

The following are explicitly outside the model. The first two are undetectable through reflection; the rest are detectable and reliably make the dispatch not applicable.

| Construct | Behavior |
| --------- | -------- |
| *using*-declarations naming `Impl` | Reflection does not enumerate `using`-declarations, so they never take effect: a `using`-declaration that re-exports hidden base overloads into a derived class does not unhide them, and one that widens access — e.g. re-exporting from a non-public base class or a non-public member — does not make the member visible. Conversely, a `using`-declaration needed only to disambiguate sibling bases is assumed present (see above). |
| Member function templates | Never participate. A call that member overload resolution would resolve to a template specialization is either not applicable or resolves to a non-template overload of `Impl`. |
| `volatile`-qualified member functions | Skipped. [*ProOverload*](../ProOverload.md) defines no `volatile` overloads, so no convention can produce a `volatile`-qualified operand. |
| Non-public members and non-public inheritance | Only members and base classes accessible from outside the class hierarchy are considered. |
| Operators and conversion functions | Not addressable by name; covered by [`operator_dispatch`](../operator_dispatch/README.md), [`explicit_conversion_dispatch`](../explicit_conversion_dispatch/README.md), and [`implicit_conversion_dispatch`](../implicit_conversion_dispatch/README.md). |

## Accessibility

The generated [accessor](../ProAccessible.md) contains a data member named `Func` of an unspecified callable type, defined via `std::meta::define_aggregate`, providing one `operator()` per overload of the convention. A call expression `p.Func(args...)` therefore works as with the macro, but `Func` is a data member rather than a member function: `&decltype(p)::Func` is a pointer to data member, and `p.Func` is a valid expression on its own.

## Example

```cpp
#include <iostream>
#include <string>
#include <vector>

#include <proxy/proxy.h>

#if __cpp_impl_reflection >= 202506L

struct Dictionary : pro::facade_builder //
                    ::add_convention<pro::mem_dispatch<"at">,
                                     std::string(int index) const> //
                    ::build {};

int main() {
  std::vector<const char*> v{"hello", "world"};
  pro::proxy<Dictionary> p = &v;
  std::cout << p->at(1) << "\n"; // Prints "world"
}

#else

int main() { std::cout << "C++26 reflection is not available\n"; }

#endif // __cpp_impl_reflection >= 202506L
```
